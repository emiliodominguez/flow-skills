# 2026-09-27: routing and with/without proxy runs

No API credentials were configured, so `pnpm eval:triggers` and `pnpm eval:ab` exited 2 (not run).
These proxy runs used isolated subagents instead. They are weaker evidence than the scripted
runs: one sample per prompt, a small routing model, and answers written without tools.

## Routing

A small model saw only the name-and-description index (as a host loads it) and 245 shuffled,
unlabeled prompts from `triggers.json`, in five batches keyed by request number.

- First pass: 241/245 (98.4%). Should prompts 137/140, near misses 104/105.
- Misses: two first-tour requests went to `flow-repo-brief`, one "agents ignore a skill"
  request went to `flow-prune-agent-setup`, and one production 500s request went to
  `flow-triage` (a defensible pick; the prompt's expectation was changed instead).
- Fixes: sharper descriptions for `flow-onboard`, `flow-repo-brief`, `flow-write-skill` and
  `flow-prune-agent-setup`.
- Recheck of the 49 prompts owned by the changed skills and their neighbors: 48/49. The miss
  sent "refresh stale subsystem notes" to `flow-docs`; `flow-repo-brief` now claims agent notes
  and `flow-docs` human-facing docs. Not rerun after that last change.

## With/without answers

A small model answered all ten `ab.json` cases once with the skill body and once without. A
separate judge graded both answers per case against the assertions, with the labels shuffled
so it could not tell which answer had the skill.

| Case                         | With    | Without |
| ---------------------------- | ------- | ------- |
| verify-worker-claim          | 100%    | 20%     |
| review-staged-layer          | 100%    | 75%     |
| diagnose-intermittent        | 80%     | 60%     |
| test-flaky                   | 100%    | 100%    |
| work-done-claim              | 100%    | 50%     |
| pr-feedback-wrong-suggestion | 100%    | 100%    |
| api-breaking-change          | 100%    | 60%     |
| observe-silent-job           | 75%     | 50%     |
| write-skill-gap              | 100%    | 25%     |
| commit-message-only          | 100%    | 100%    |
| **Mean**                     | **96%** | **64%** |

No assertion was worse with the skill. Three cases passed either way because their prompts
gave the answer away; those prompts and assertions were rewritten (see the rerun below). Two
assertions failed either way: a regression check for the diagnosed cause, and an alert with
threshold, routing and runbook together. Both are in the skills, so the answers (capped at 350
words) likely dropped them; watch them in scripted runs.

## Rerun of the rewritten cases

| Case                         | With | Without |
| ---------------------------- | ---- | ------- |
| test-flaky                   | 60%  | 60%     |
| pr-feedback-wrong-suggestion | 100% | 20%     |
| commit-message-only          | 60%  | 60%     |

The harder prompts now separate the variants for `flow-pr-fix`, and they exposed two skill gaps.
Under "I need green today" pressure, the `flow-test` answer did not reject a retry or mention
quarantine ownership. The `flow-commit` answer to a message-only request described committing
and omitted the user-visible effect. Both skills were patched: a red flag for deadline pressure
in `flow-test`, and a mode decision up front plus a user-visible-effect example in `flow-commit`
(deliberately from a different domain than the eval, to avoid fitting the test).
`flow-diagnose` now names the check that will prove the eventual fix in its first step.

## Limits

One sample per variant, one answering model, no tool use, and assertions written by the same
author as the skills. Treat the deltas as direction, not effect size. Rerun with
