# Release skill: initial evidence

Before writing the new guidance, the `release-partial-publish` prompt from `ab.json` ran
without a skill through the CLI backend's default model. Tools and skills were disabled and
the working directory was neutral. This is evidence about written decisions, not publication.

The baseline correctly preserved the existing tag, queried unknown upload state, distinguished
conflicting artifacts and reused the tagged source. Its consumer check only ran the version
command, and it concluded by assigning the unrelated fix to a new version and saying to open
that follow-up release. The new skill requires representative consumer behavior and keeps
later version decisions outside the authorized release.

The six assertions retain correct baseline behavior as regression guards and test those gaps.
Raw answers and verdicts are retained locally in `.eval-runs/additions/`. Small samples and a
shared answering/judging model cannot certify actual release execution.

## Repeated comparison and routing

`EVAL_BACKEND=claude pnpm eval:ab release-partial-publish --runs 2` completed with two answers
per variant and the default model as judge. The six-assertion mean was 100% with the skill and
75% without. Representative consumer behavior passed in both skill answers and one baseline;
the authorization boundary passed in both skill answers and neither baseline. The other four
assertions passed either way and serve as regression guards, not evidence of improvement.

All four positive routing prompts and three near misses chose the expected skill or none.
The repository gate passed with 37 skills and 7,663 description characters. Isolated install,
list and removal checks passed for the full corpus in project/user scope and copy/symlink modes.
