# Automated behavioral execution

The new runner executed the three existing fixtures through CLI 2.1.283 on macOS with Node
26.5.0. No model override was supplied; executor transcripts reported `claude-opus-5-5`.
Each assessment used a separate fresh CLI completion. The rubric was not passed to executors.

| Scenario              | Variant       | Behavioral result | Observed task outcome                                                                                                 |
| --------------------- | ------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------- |
| staged-review         | with skill    | PASS              | Identified the staged access-control defect, distinguished the corrected working file and preserved the source/index. |
| contract-verification | with skill    | PASS              | Rejected the quantity calculation, evaluated all criteria and ran the real existing tests.                            |
| resume-budget         | with skill    | PASS              | Preserved the three consumed attempts and historical verdicts; kept dependent tasks blocked.                          |
| staged-review         | without skill | PASS              | Also identified the staged defect without modifying the fixture.                                                      |

The staged-review skill run passed twice during integration. The full three-case run and the
separate no-skill run used the same bounded fixture capabilities: list, read, write, Git-layer
inspection and the configured trusted test command. Actual startup inventories contained only
those five tools and the explicitly configured fixture server. Raw evidence remains local in
`.eval-runs/behavior-all`, `.eval-runs/behavior-connected` and `.eval-runs/behavior-baseline`.

## Harness failures caught before delivery

- Safe mode disabled even the explicitly configured fixture server. The initial run timed out
  with no tool events and correctly recorded ERROR; no behavioral pass was claimed. The runner
  now disables ambient settings, skills, hooks, memory and MCP separately while enabling its server.
- Review reproduced a mixed-case Git-directory path escape on a case-insensitive filesystem.
  The path guard now rejects aliases and Git operations explicitly disable executable monitors.
- Timeout and cancellation checks now kill remaining process-group descendants even when the
  immediate parent has already exited. Executor and assessor use the same bounded lifecycle.

Fifteen deterministic harness tests cover real fixture preparation, MCP requests, trusted test
execution, traversal and Git alias rejection, preserved files, missing evidence, malformed
results, timeout descendants and interruption. Two independent read-only review passes
reproduced the defects and verified the corrections. No model calls run as part of these tests.

## Limits

These are small, curated exercises with one observed executor model and a constrained tool set.
Staged review passes with and without the skill, so this run demonstrates a regression guard,
not a measured skill benefit. The other scenarios have no automated baseline comparison in
this record. A behavioral PASS means the scenario's requirements passed; it does not mean an
incorrect worker artifact was accepted or that every host/model behaves the same way.
